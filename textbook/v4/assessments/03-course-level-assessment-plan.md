# Course-Level Assessment Plan

## Purpose

This file defines the course-level assessment architecture for `ITM-2100 v4`.

It translates the v4 course design into a workable assessment system for a fully asynchronous, AI-available course.

## Course-Level Assessment Rule

In `v4`, the course does not treat polished artifacts alone as strong evidence of learning. Major assessments must instead require students to explain, diagnose, compare, adapt, verify, or defend.

## Repeating Course Pattern

Each major unit should follow this sequence:

1. instructional content and guided practice
2. AI-allowed production work or artifact drafting
3. second evidence task that tests explanation, diagnosis, or adaptation
4. revision based on new constraints or detected flaws

## Course-Level Assessment Categories

### 1. Timed Quizzes and Short Case Checks

Purpose:

- test recognition, interpretation, classification, and short-form reasoning

Recommended uses:

- workflow classification
- SQL reading
- data-model concept checks
- dependency and key reasoning
- artifact-boundary classification
- implementation verification
- operations scenarios

### 2. Critique, Diagnosis, and Repair Tasks

Purpose:

- make students evaluate flawed work instead of only producing polished work

Recommended uses:

- flawed ERD critique
- wrong query analysis
- decomposition comparison
- mixed-up ERD versus DBDD repair
- schema or view audit

### 3. Annotated or Recorded Explanations

Purpose:

- reveal whether the student can explain a choice, not just submit an answer

Recommended uses:

- short screencast defense
- annotated query explanation
- critique rationale
- conversion explanation
- procedural-choice defense

### 4. Revision and Change-Request Work

Purpose:

- test adaptation, consistency, and system-level understanding

Recommended uses:

- design repair
- build correction
- operations-plan improvement
- final project change response

## Weighting Target

Use this weighting range unless a delivery constraint requires a minor adjustment:

- `30 to 40 percent` timed quizzes and short case checks
- `25 to 35 percent` critique, diagnosis, and repair tasks
- `15 to 25 percent` annotated or recorded explanations
- `15 to 25 percent` revision and change-request work

## Capstone-Level Assessment Artifacts

The course-level capstone evidence should come primarily from:

- Module 8 `Change Request Revision`
- the cross-module final project package
- explanation of why the revised package is coherent and trustworthy

The final project should therefore not be graded as a polished artifact bundle alone. It should be paired with revision, verification, and defense requirements.

## Shared Grading Priorities

Across the course, the strongest evidence is:

- explanation of why a choice is correct
- diagnosis of flaws, risks, or inconsistencies
- adaptation when business rules change
- verification that outputs satisfy stated requirements
- judgment about whether AI-generated work is trustworthy
- justification of responsible data, design, reporting, access, and automation choices where appropriate

## Minimum Course-Wide Requirements

- Every major artifact-producing task must have a second evidence type.
- Lesson-level checks should feed directly into module-level assessments.
- Module-level assessments should prepare students for the final project revision and defense pattern.
- Christian integration should remain embedded inside assessment scenarios, examples, risks, and decision prompts rather than separated into stand-alone reflection tasks.

## Recommended Instructor Use

Use this file when:

- mapping assessments into the LMS
- deciding which tasks are graded and which are practice only
- writing rubrics
- checking whether a proposed assignment can still reveal understanding in an AI-available course

# ITM-2100 v4 Running Cases

## Purpose

This directory defines the recurring case studies used across `ITM-2100 v4`.

## Case Policy

- The primary running case is `Lakeside Tutoring Center`.
- The alternative case is `Cedar Valley Community Clinic`.
- Early modules should use the simple initial case designs because they are easier for students to follow.
- Later modules, especially Module 7 and Module 8, may revisit the same cases as redesign problems.

## Files

- `lakeside-tutoring-center-primary-case.md`
  Primary running case for lessons, examples, assignments, and project-style checkpoints.
- `cedar-valley-community-clinic-alternative-case.md`
  Alternative case for further discussion, comparison, or extension activities.
- `user-role-redesign-progression.md`
  Late-course redesign note showing how the simple person-table designs can evolve into a more flexible `User` and `Role` model.

## Teaching Sequence

Use simple designs first. Students should learn entities, attributes, relationships, ERDs, DBDDs, SQL, and basic operations before they are asked to evaluate abstraction tradeoffs.

Bring up the redesign later, after students understand enough to answer these questions:

- what problem does the redesign solve?
- what tables and relationships change?
- what gets more flexible?
- what gets more complex?
- what breaks if the redesign is done carelessly?

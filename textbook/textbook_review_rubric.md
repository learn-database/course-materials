# ITM-2100 Textbook Draft Review Rubric

This rubric is for reviewing draft textbook chapters against the requirements in [agents.md](agents.md) and the learning-outcomes map in [itm2100_textbook_plan.md](itm2100_textbook_plan.md).

## How to score

Score each category using this scale:

| Rating | Description |
| --- | --- |
| 4 | Fully meets the stated requirement with no meaningful revision needed |
| 3 | Mostly meets the requirement; minor revision needed |
| 2 | Partially meets the requirement; clear revision needed |
| 1 | Minimally meets the requirement; major revision needed |
| 0 | Missing, inaccurate, or not aligned to the source requirements |

Calculate each weighted score as `(rating / 4) x category weight`. A perfect score is 100.

## Review categories

| Category | Weight | What to look for |
| --- | ---: | --- |
| Outcome alignment | 20 | The chapter clearly supports its listed chapter outcomes and section objectives. Coverage is not generic; it matches the plan for that specific chapter. |
| Required chapter structure | 20 | The chapter includes all required parts: Title, Purpose, Learning outcomes, Section-by-section draft prose, Worked examples, Common mistakes, Quick check, Lab, Project checkpoint, and Key terms. |
| Technical correctness | 20 | Database and SQL Server concepts are accurate for the level of the chapter. SQL terminology is correct. Query examples, joins, grouping, schemas, constraints, and object descriptions are technically sound where applicable. |
| Project and milestone support | 15 | The chapter clearly supports the semester project and reinforces the milestone flow: proposed entities, ER diagram, database design diagram, and SQL Server implementation. |
| Clarity and level | 10 | The prose is plain, concise, instructor-friendly, and appropriate for undergraduate readers. The writing teaches rather than lists notes. |
| Examples and applied practice | 10 | Worked examples, quick checks, labs, and project checkpoints are realistic, business-oriented, and aligned to what students should do next. |
| Consistency and production readiness | 5 | Headings are consistent across chapters, terminology is consistent, Markdown is clean, and the draft appears compatible with later DOCX conversion. |

## Performance descriptors by category

### 1. Outcome alignment

| Rating | Descriptor |
| --- | --- |
| 4 | Every major section maps cleanly to the chapter outcomes and section objectives in the plan. Nothing important from the mapped outcomes is missing. |
| 3 | Most outcomes and objectives are addressed, with only small gaps or slight imbalance in coverage. |
| 2 | Some important outcomes are addressed, but the chapter misses multiple planned objectives or drifts into less relevant content. |
| 1 | Alignment is weak; the chapter only loosely reflects the intended outcomes. |
| 0 | The draft does not match the planned outcomes for the chapter. |

### 2. Required chapter structure

| Rating | Descriptor |
| --- | --- |
| 4 | All required components are present and clearly labeled. Each component contains substantive draft material rather than placeholders. |
| 3 | All components are present, but one or two are thin or unevenly developed. |
| 2 | Several required components are present, but one or more important parts are missing or underdeveloped. |
| 1 | Only a partial chapter shell exists. |
| 0 | The required structure is largely missing. |

### 3. Technical correctness

| Rating | Descriptor |
| --- | --- |
| 4 | Technical explanations and examples are accurate, use SQL Server terminology correctly, and avoid misleading simplifications. |
| 3 | The chapter is mostly accurate, with only minor wording or precision issues. |
| 2 | The chapter includes noticeable technical errors, ambiguous explanations, or examples that need correction. |
| 1 | Technical reliability is weak enough that students could learn incorrect concepts or habits. |
| 0 | The chapter is substantially inaccurate or unreviewable. |

### 4. Project and milestone support

| Rating | Descriptor |
| --- | --- |
| 4 | The chapter clearly advances the semester project and explicitly supports the relevant milestone flow. |
| 3 | The project connection is present and useful, though not consistently reinforced. |
| 2 | The project connection appears briefly but does not strongly guide student work. |
| 1 | The project link is vague or mostly absent. |
| 0 | The chapter does not support the semester project. |

### 5. Clarity and level

| Rating | Descriptor |
| --- | --- |
| 4 | The prose is clear, concise, readable, and appropriately instructional for undergraduate learners. |
| 3 | The prose is generally clear, with minor density, repetition, or wording issues. |
| 2 | The chapter is understandable in places but too terse, too dense, or too note-like. |
| 1 | The prose is difficult to follow or poorly matched to the intended audience. |
| 0 | The draft is not usable as instructional prose. |

### 6. Examples and applied practice

| Rating | Descriptor |
| --- | --- |
| 4 | Examples and activities are realistic, business-based, accurate, and clearly reinforce the learning outcomes. |
| 3 | Practice material is useful, with only minor alignment or realism issues. |
| 2 | Practice material exists but is generic, thin, or only partly aligned to the chapter goals. |
| 1 | Practice material is weak, confusing, or minimally developed. |
| 0 | Practice material is missing. |

### 7. Consistency and production readiness

| Rating | Descriptor |
| --- | --- |
| 4 | Formatting, heading patterns, terminology, and Markdown structure are consistent and ready for downstream conversion. |
| 3 | Minor consistency or formatting cleanup is needed. |
| 2 | Inconsistencies are frequent enough to slow editing or conversion. |
| 1 | The chapter needs major cleanup before it can move forward. |
| 0 | The file is not in usable review shape. |

## Use guidance

- Use this rubric to review draft quality, not to introduce new chapter requirements beyond the source files.
- If source material is missing, mark the issue explicitly instead of guessing.
- If a technical claim is uncertain, flag it for verification against official documentation.
